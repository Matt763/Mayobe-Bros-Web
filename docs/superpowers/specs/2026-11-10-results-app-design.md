# Results app on the NECTA results posts (design and build contract)

Approved by the owner on 2026-11-10: override the "no result lists, names or numbers, empty body" rule; data stays outside git for now (local folder, host chosen at deploy time); include PSLE (no PREM numbers).

## What the visitor sees
A post with `app: results` (the nine `necta-{csee,acsee,psle}-results-{2025,2024,2023}` posts) keeps ONLY the site navbar (`header()`). Everything else of the blog is gone (hero, article, rail, share, comments, read-next, footer). The page body is the Results look ported from `/run/media/mclean/New Volume/MY WEBSITE PROJECTS/Mayobe Results Website` (read-only, never edit it):
1. **Exam view** (`/post/educational/results/necta-csee-results-2024/`): navy hero (crumbs Home / Results / CSEE / 2024 on our own URLs, eyebrow, H1 "CSEE Examination Results 2024", lead, 3 stats, "Other years" links to sibling results posts), tools (3 search fields: school or centre name, centre number, candidate number), A-Z bar with counts, centre list (2 columns on wide screens, 200 per page, pager), a short real explainer + the independence/not-NECTA statement + official NECTA link + data date, and a slim strip (Terms, Privacy, Cookie settings button `data-cookie-settings`).
2. **Centre view** (same page, `?centre=P0101`): hero with centre name, division summary table, candidate search + division chips, full candidate table (stacked cards on phones), overall-performance blocks, back link. `?centre=P0101&cno=0001` also shows the "Your result" card and marks the row.
3. Posts with no dataset (csee-2025, acsee-2025, psle-2024, psle-2025): same hero, an honest plain statement that these results are not on the site and a link to NECTA and to the years that are; `noindex`, not in the sitemap. No "coming soon" wording.

## Data contract (v3), folder `results-data/` (git-ignored), served at `/results-data/`
Per exam-year (one tiny file per centre; years are never merged): `meta.json`, `list.json` and `<lowercode>.txt`. A centre page needs only `meta.json` and its own file, never the list. About 74% smaller than v2 (19 MB raw, 8.6 MB gzip for the first five exams). Lab figures and the experiments behind it: `~/.cache/mb-size-lab/`.
- `meta.json`: `{"v":3,"exam","cat","year","kind","verified","total","online","key",...}` plus the tables every centre needs: `subjects` (canonical NECTA order, so a candidate's subjects are always ascending), `sw` (sequence width), `ut` (source URL template with `{c}`), `nc` (name suffixes), `sx` (`["F","M"]`), `pts` (grade points), `tpl` (shapes of the summary, overall and facts blocks), `lv`/`lf` (level tables); secondary: `rule` (best-k points for the aggregate, 0 = stored), `ps`, `dv` (division table), `sm` (subject code and name), `regions`; primary: `pd` (dictionary of the whole grade strings) and `vc` (its variable-length code). `key` = first 10 hex of the sha1 of meta (without key) + list. `online` counts centres with a file.
- `list.json`: the centre list in columns (`c` delta-coded codes, `x`/`k`/`n` name suffix dictionary, `z` or `y` the centres without or with a file, `R/r/D/d` run-length region and district); `decodeList(list, kind)` returns rows `[code, listName, has, region?, district?]` sorted by code.
- `<lowercode>.txt`, ten lines: 0 header `seq;name;url;summaryMode;overallMode;factsMode;counts;absent;code` (seq empty for 1..N, else `r1-5,7-9` or `l`+list; name = `k:stem`, suffix `nc[k]`; url empty when it follows the template; counts = per sex and division I..0, or per Average Grade A..E; code only when not in capitals) / 1 sex as run-lengths (`F502M427`) / 2 marker rows (`pos\taggt\tdiv\tnote`, PSLE `pos\tnote`; withheld, nullified, repeat, transferred ...) joined by `\x1f` / 3 local subject list (base62) / 4 grades: fixed-width block per candidate (`.` = not taken), PSLE a code into `meta.pd` / 5 explicit aggregates (only when `rule` is 0) / 6 exceptions `k,aggt,div` / 7 stored numbers (region index and centre GPA; PSLE marks totals) / 8 patches `[[cell,text]]` / 9 whole blocks `[summary,overall,facts]`. Summary, overall blocks and facts are worked out from the rows (and the header counts) and patched; a block the rows cannot predict is stored whole (mode `j`). The header alone gives n, absent and the counts per sex and division (`decodeHeader`, `stats` in the codec): pass rate = candidates with a division I to IV divided by candidates who sat.
- Encoder `scripts/lib/results-pack.mjs` (`learnMeta`, `packCentre`, `packList`, `verifyCentre`, `verifyList`), writer `scripts/results-data.mjs`: it decodes every file again and compares name, URL, summary, overall, facts and every candidate with the source (cno, sex, aggt, div, grade, subjects, note, regenerated `subjectsRaw`); any difference writes nothing and exits 1. Partial exams are fine (only centres with a file are online).
- Decoder `js/results-codec.js` (ES module for the browser, Node and Cloudflare Workers; no DOM, no Node APIs): `decodeCentre(text, meta, code)` returns
  `{code,name,sourceUrl,summary:{head,rows}|null,facts:[[k,v]],overall:[{t:'h',v}|{t:'kv',rows}|{t:'grid',head,rows}],candidates:[{cno:'P0101/0001',sex,aggt,div,grade,subjects:[[name,grade]],note}]}`.
  `div` for secondary exams, `grade` (Average Grade letter) for PSLE, `note` only for marker rows. Candidate numbers stay strings. `prem` is never exported.
- Fix in the packer, not in the Results project: a centre file or code that is lowercase there (S5405, S1939, P5980) must still appear if its JSON exists; report what is missing, do not invent rows.

## Page contract
- `scripts/lib/results-app.mjs` exports `resultsAppHtml(post, ctx)` -> string for inside `<main id="main">`. `ctx = { u, e, icon, config, dataset|null, siblings:[{label,href,current}], crumbs:[{name,href}], official:url|null, verified, cacheKey }`. Root: `<div class="rs" data-rs data-exam data-cat data-year data-kind data-base="/results-data" data-path="/post/...">`. No inline script, no `style=` attributes, no `<article class="post">`, no `.hero`/`.pagination`/`.wrap`/`.section` classes (all `rs-` prefixed).
- `js/results-app.js` (ES module, imports `./results-codec.js`) boots from the `data-*` attributes only (never from the URL path). `css/results.css`, every rule under `.rs`. Fonts self-hosted in `assets/fonts/` (Manrope, Newsreader latin from the Results project, `font-display: swap`).
- URL state: exam view `?q=&code=&cand=&letter=&p=`; centre view `?centre=&cq=&grade=&cno=`. `pushState` for opening/closing a centre and pager; `replaceState` for typing. Back closes the centre and restores the list, filters and scroll. Opening a centre sets `document.title`, hero and `meta[name=robots]` to `noindex, follow`; leaving restores them. Canonical never changes.
- Candidate-number field: a number with a sequence offers an explicit "Open result" button / Enter (no automatic navigation after a timer); without a sequence it filters centres by code prefix.

## Rules (the project's CLAUDE.md applies in full)
CSP: script-src 'self'; no inline JS/handlers; all data inserted with textContent/DOM builders. Motion only through `window.MBMotion` (`glide`, `topOf`, `enter`); no `scrollTo({behavior})`, no `scrollIntoView({behavior:'smooth'})`, `focus({preventScroll:true})`. Reduced motion respected. Visitor-facing strings follow `scripts/tests/messages.test.mjs` (no "Sorry", "Please", "!", technical words). Dark mode: light area uses `--rs-*` variables that follow the site's `html.dark` / prefers-color-scheme; the hero stays navy. `html.js` scope for the skeleton rules in CLAUDE.md still applies. Tap targets at least 44px on touch. Names with apostrophes must match without them ("marys" finds "MARY'S"). Table semantics kept; on phones tables become stacked cards via CSS that keeps real `<table>` markup (use `role` fixes where `display:block` removes semantics). Tools block sticks under the site header only if it leaves enough screen (measure at 1280x800).

## Defects found in the Results code, to fix in the port
`a.row[role=listitem]` hides the link role; no-match centre search hid the summary table (first `.table-wrap`); double live region on the status line; candidate lookup downloaded a whole HTML page; automatic navigation 350 ms after an exact number; division chips showing raw markers with no explanation (show "Not graded" / the note text and a short legend); `lang="sw"` for Swahili PSLE captions; focus lost when the clear button or pager removes the focused element; `?` keys must be namespaced.

## Out of scope now
Hosting the data (R2 or other), per-centre indexable URLs, a grade calculator, Popular ranking for results pages, comments on results posts.

# Addendum 2026-11-10 (later): more years, indexable pages on mayobebros.com

Owner's request: real data for every results post (2025 to 2020 for CSEE, ACSEE and PSLE), served from mayobebros.com and indexable there (not only on NECTA), data as small as possible. Sources, verified: NECTA `onlinesys.necta.go.tz` (CSEE 2022 and 2025, ACSEE 2025, PSLE 2022, 2024, 2025), Maktaba Tetea mirror `maktaba.tetea.org/exam-results/` (CSEE 2020, 2021, ACSEE 2020 to 2022, PSLE 2020, 2021). Candidate NAMES (in PSLE 2020 and 2021 mirror pages) and PREM numbers are never stored. Importer: `scripts/necta-import.mjs` (resumable, 1 worker, 1 request/s per host: faster rates made NECTA's server slow down to 12 to 20 s per page). Work files: `$HOME/necta-work/`. Format v3: see "Data contract" above (meta.json, list.json, one `<code>.txt` per centre per exam-year, about 74% smaller than v2).

## Indexable pages: Cloudflare Worker on `mayobebros.com/results/*` (project `results-worker/`)
GitHub Pages cannot hold 150,000 pages, so a Worker renders them on demand from the R2 bucket `mayobe-results-data` (same objects the browser app reads), caches them at the edge, and the rest of the blog stays on GitHub Pages. Needs Workers Paid ($5/month) for production (free plan: 100,000 requests a day shared with crawlers and 10 ms CPU).
- **URLs** (lowercase codes): `/results/<cat>/<code>/` centre overview (all years: counts per division, pass rate, links to each year); `/results/<cat>/<code>/<year>/` centre-year page (facts, summary table, full candidate table as plain HTML, source link and check date); `/results/<cat>/<year>/<letter>/` and `/results/<cat>/<year>/<letter>/<n>/` crawlable A-Z centre lists (200 per page); PSLE also `/results/psle/<year>/region/<slug>/` and `/district/<slug>/` hubs. The exam post (`/post/educational/results/necta-<cat>-results-<year>/`) stays the interactive hub and links to the A-Z lists. Unknown code or year: real 404. Codes in upper case or with a trailing path: 301 to the lowercase canonical.
- **Indexing switch** `resultsData.index` in `site.config.json` (shipped as Worker var `RESULTS_INDEX`): `"off"` (default until the owner decides; recommended until AdSense approval: Google's reviewers see every indexable page): every Worker page sends `X-Robots-Tag: noindex, nofollow` and `<meta robots>`, sitemaps are empty (404), and no static page links to them; `"hubs"`: overview and A-Z pages indexable, year pages noindex; `"all"`: everything indexable that passes the quality bar (year page needs at least 20 candidates who sat; overview needs at least one year). Never `index` a page that fails the bar.
- **Page content** (English only; AdSense does not allow primarily-Swahili pages; keep NECTA's own labels in the table): unique title and description built from computed facts (`{Centre name} ({CODE}) {EXAM} {year} results: {n} candidates, {pass}% pass`), one H1, breadcrumbs (visible and BreadcrumbList), the Results look (`css/results.css`, same hero and tables), the site navbar and footer from the shell, a plain "how to read this" paragraph and the definitions of divisions, "Source: NECTA (via Maktaba Tetea for 2020 to 2022 where that is the source)" with the real source URL and the check date, the independence statement, and a correction/removal link to /contact/. No names, no PREM. Statistics only from the data (counts per division, share of candidates with a division I to IV, year-to-year change). Neutral wording; no rankings or "best school" language.
- **Shell:** `node scripts/build.mjs` writes `results-shell.html` (site head with CSP, navbar, footer, skeleton, with tokens `%%TITLE%%`, `%%DESC%%`, `%%PATH%%`, `%%ROBOTS%%`, `%%JSONLD%%`, `%%MAIN%%`); it is `noindex` and disallowed in robots.txt. The Worker fetches it from the origin once per isolate and fills the tokens. Page CSS/JS are the same `css/results.css` and `js/results-app.js`; the app boots in "centre mode" on these pages (`data-mode`, `data-centre`, `data-year`), replacing the server-rendered table with the interactive view (search, division chips, phone cards) after fetching the same `.txt` file.
- **Links:** when `resultsData.pages` is true, centre rows in the exam page link to the Worker URL; otherwise they keep `?centre=` (local preview, before deploy). The `?centre=` view stays working for old links.
- **Sitemaps:** `/results/sitemap.xml` (index) and `/results/sitemap-<cat>-<year>-<n>.xml` (at most 10,000 URLs each; only canonical indexable URLs; real `lastmod` = the data's `verified` date). The root `sitemap.xml` built by the blog lists the Worker's index. IndexNow is run by the owner in waves.
- **Cache and limits:** `Cache-Control: public, max-age=3600, s-maxage=2592000, stale-while-revalidate=86400`; Workers Cache enabled in the Worker config if available, otherwise the Cache API; one R2 read per centre-year, overview reads the header line of each year in parallel; decode only what the page needs (`decodeHeader` for overview/lists).
- **Local preview:** `scripts/serve.mjs` hands `/results/*` to the same handler (a filesystem shim stands in for R2 reading `results-data/`), so the owner can look at every page on http://127.0.0.1:8000/results/... before deploying.
- **Tests:** a fake R2 binding; URLs, 404/301, robots by switch, titles/descriptions unique and within length, no names/PREM, sitemap limits, CPU-light render of the largest centre.
