Caching means keeping a copy of a file so it does not have to be downloaded again. This helps pages open faster and uses less mobile data. This page explains how it works on {{site-name}}.

How the site is built

{{site-name}} is a static website. Every page is a ready-made file served from GitHub Pages, so there is no database behind the article pages. We do not use a service worker, so the site does not store an offline copy of itself on your device.

What is cached and for how long

  • Pages and files. GitHub Pages and its network tell your browser it may reuse a file for a short time, normally around ten minutes. After a new article is published it can take a few minutes to show for everyone.
  • Styles and scripts. Their web addresses change when we update them, so you always get the newest design and behaviour.
  • Pictures. Images on the site do not change, so your browser may keep them longer.
  • Search. The search list is downloaded the first time you search and reused afterwards.
    • {{#comments}}
  • Comment and reaction counts. These are kept for about thirty seconds to a minute, so a new comment or reaction may take a moment to show in the totals.
    • {{/comments}}

Privacy

We never cache private information. Cached files are the same public files every visitor receives. The small items stored in your browser are listed in the Cookie Policy.

See the latest version

  • Reload the page. On a computer press Ctrl + Shift + R (Windows or Linux) or Cmd + Shift + R (Mac).
  • On a phone, close the tab and open the page again, or clear the browser's cache in its settings.

If a page still looks out of date after a few minutes, please tell us.
